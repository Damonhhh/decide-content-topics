## 账号定位问卷与定位档案

账号定位至少说明：

- 账号主要讲什么；
- 目标观众是谁；
- 观众最常见的问题；
- 创作者已经拥有的经验、案例或素材；
- 账号偏好的内容交付物；
- 不做或谨慎处理的内容。

没有已确认定位文件时，只检查用户明确提供的信息能否同时回答“讲什么、讲给谁、凭什么由你讲、观众带走什么”。任意一项无法直接回答，都视为信息不足：复制 `assets/templates/input/account-positioning-questionnaire.template.md`，生成 `00-账号定位问卷.md`，请用户填写后停止，不根据零散介绍补猜。四项必须分别能引用用户原话；主题标签不能同时推断受众，身份不能自动充当创作者优势，内容形式不能自动充当观众交付物。收到答案后复制 `assets/templates/input/account-profile.template.md`，生成 `02-账号定位与受众.md` 草稿，并等待用户确认。未经确认，不得把推测写成最终定位，也不得继续生成候选选题。

## 近期内容与重复检查

建议提供最近 3—10 条已经制作或发布的内容。每条至少说明标题、核心判断、目标观众问题、使用的案例或证据、观众交付物和表达角度。发布状态不确定时，也按“已经制作”参与去重。

- 已运营账号缺少近期清单：生成空白 `03-近期内容摘要.md`，请用户补充后停止。
- 全新账号确实没有历史内容：允许用户明确确认“空基线”，但必须记录这一事实，不能把 `NEW` 自动打成高分。
- 收到近期内容后：生成 `06-近期内容重复检查.md`，从受众问题、核心判断、案例证据、交付物、表达角度和画面形式六个维度判断重复程度。

重复检查完成前，不得给候选的 `NEW` 项打分。

## 信息源雷达与信息快照

公开版 Skill 只提供雷达结构，不附带作者真实使用的网站、账号、群聊、订阅地址或私有配置。用户需要自行填写：

- 长期关注的主题和关键词；
- 本轮优先检查的公开来源；
- 时间窗口与采集上限；
- 明确排除的来源、主题或高风险内容；
- 当前环境实际可用的检索工具。

雷达有三个状态：不存在、待补充或待确认、已确认。不存在时生成空白 `01-信息源雷达配置.md` 并停止；空白文件归入“待补充或待确认”，字段不完整或没有得到用户明确确认时，列出缺项并停止；只有字段完整且用户明确确认后才能执行。文件存在本身不构成执行授权，“开始选题”也不构成雷达确认。如果用户已经提供一份可核验的信息快照，可以跳过雷达配置，直接读取快照。

雷达只规定“去哪里找、找什么、找多长时间”，不直接决定选题。没有可用检索工具、没有快照且项目中不存在雷达时，公开采集路线不可执行，不要求新建雷达；复制 `assets/templates/input/signal-snapshot.template.md` 为 `04-信息快照.md` 空表并停止。若项目中已经存在待补充或待确认的雷达，该状态优先于无工具降级：先列出缺项并停止；只有用户明确放弃该雷达并选择手工快照路线，才生成空白 `04-信息快照.md`。只有用户明确要求配置未来可用的雷达时才优先处理 `01`。不得声称已经实时采集，也不得继续重复检查、筛选或候选生成。

无论由雷达采集还是由用户提供，先统一形成 `04-信息快照.md`。每条信息至少说明：

- 信息名称；
- 来源；
- 发布时间或采集时间；
- 当前可以确认的事实；
- 证据状态；
- 已知风险。

缺少来源或时间的信息可以参与观察，但不能被包装成已经核验的强证据。

## 评分规则与硬闸门

默认使用本 Skill 的七项评分和硬闸门。用户可以根据账号类型调整权重或补充禁区，但不得删除来源核验、近期内容重复检查、证据边界和人工确认。

## 信息筛选表

`08-信息筛选表.md` 每条信息包含：

| 字段 | 要求 |
| --- | --- |
| 信息 | 一句话说明信号是什么 |
| 来源与时间 | 保留核验线索 |
| 与受众的关系 | 说明为什么与该账号观众有关或无关 |
| 可用证据 | 区分事实、来源方主张和待核验内容 |
| 重复检查 | 引用 `06-近期内容重复检查.md`，标记相同、相近或新增 |
| 观众带走物 | 暂时能交付什么；没有就直说 |
| 主要风险 | 证据、合规、误导、距离或画面风险 |
| 处理结果 | 进入候选、继续观察或淘汰 |
| 处理理由 | 写清决定依据，不只写综合印象 |

## 候选选题比较

`09-候选选题比较.md` 先写比较结论，再分别展开候选。每个候选包含：

1. 暂定标题；
2. 观众问题；
3. 信号来源；
4. 一句话核心判断；
5. 观众带走物；
6. HP、TA、CASE、PROOF、SAVE、NEW、VISUAL 七项分数及理由；
7. 硬闸门检查；
8. 最强反对理由；
9. 建议和补强动作。

不要只给总分。总分可以辅助排序，但不能覆盖硬闸门。

用户否决全部候选时，在本文件末尾追加“人工决定”，记录“本轮不立项”、用户原话和已有淘汰理由；没有新理由时不得代编。此分支不创建 `10-选题立项卡.md`，记录后停止。

## 选题立项卡

`10-选题立项卡.md` 至少包含：

- 最终题目与备选标题；
- 目标观众正在问的问题；
- 一句话核心判断；
- 为什么现在值得讲；
- 已确认的证据；
- 仍待核实的内容；
- 观众看完能带走的具体资产；
- 内容结构；
- 画面或演示依据；
- 与近期内容的区别；
- 最大失败风险；
- 补强动作；
- 用户的人工决定；
- 交给脚本阶段的明确要求。

不要在立项卡中偷偷扩写完整口播稿。

## 阶段状态

一次运行只处于一个状态：

`等待输入 → 等待账号问卷 / 等待定位确认 → 等待近期内容 / 近期基线完成 → 雷达配置确认 / 读取快照 → 信息快照完成 → 重复检查完成 → 信息筛选完成 → 等待进入候选 → 候选比较完成 → 等待人工决定 → 已立项 / 本轮不立项`

不需要的分支可以跳过，例如已有已确认定位或用户已提供信息快照。但没有收到对应的人工决定，不得自行跃迁状态。

执行优先级固定为：账号定位确认、近期内容基线确认、取得信息快照、重复检查、信息筛选、候选授权、人工决定。每次只处理最早未满足的一层；用户对后层说“开始”“继续”或提出后层产物，都不能越过前层。已提供的有效快照可以跳过雷达配置，但不能跳过账号定位和近期内容基线。

进入候选阶段只接受以下明确授权：“进入候选阶段”“生成候选选题”，或明确要求进入 / 生成 `09-候选选题比较.md`。“继续”“下一步”“你看着办”“直接做吧”“全自动完成”等模糊表达不算授权，必须追问确认。

所有模板和参考文件从 Skill 根目录读取；运行生成的 `00` 至 `10` 号文件写入用户指定的项目目录，未指定时写入当前任务工作目录，不写回 Skill 安装目录。`assets/example-project/` 仅在用户明确要求示例演练时读取。
