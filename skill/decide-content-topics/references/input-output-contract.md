# 输入输出合同

## 目录

1. 输入要求
2. 信息筛选表
3. 候选选题比较
4. 选题立项卡
5. 阶段状态

## 输入要求

### 账号定位与受众

至少说明：

- 账号主要讲什么；
- 目标观众是谁；
- 观众最常见的问题；
- 账号偏好的内容交付物；
- 不做或谨慎处理的内容。

### 近期内容

建议提供最近 3—10 条已经制作或发布的内容。每条至少说明标题、核心判断和观众交付物。发布状态不确定时，也按“已经制作”参与去重。

### 信息快照

每条信息至少说明：

- 信息名称；
- 来源；
- 发布时间或采集时间；
- 当前可以确认的事实；
- 证据状态；
- 已知风险。

缺少来源或时间的信息可以参与观察，但不能被包装成已经核验的强证据。

## 信息筛选表

`08-信息筛选表.md` 每条信息包含：

| 字段 | 要求 |
| --- | --- |
| 信息 | 一句话说明信号是什么 |
| 来源与时间 | 保留核验线索 |
| 与受众的关系 | 说明为什么与该账号观众有关或无关 |
| 可用证据 | 区分事实、来源方主张和待核验内容 |
| 重复检查 | 与近期内容相同、相近或新增 |
| 观众带走物 | 暂时能交付什么；没有就直说 |
| 主要风险 | 证据、合规、误导、距离或画面风险 |
| 处理结果 | 进入候选、继续观察或淘汰 |
| 处理理由 | 写清决定依据，不只写综合印象 |

## 候选选题比较

`09-候选选题比较.md` 先写比较结论，再分别展开候选。每个候选包含：

1. 暂定标题；
2. 观众问题；
3. 信号来源；
4. 一句话核心判断；
5. 观众带走物；
6. HP、TA、CASE、PROOF、SAVE、NEW、VISUAL 七项分数及理由；
7. 硬闸门检查；
8. 最强反对理由；
9. 建议和补强动作。

不要只给总分。总分可以辅助排序，但不能覆盖硬闸门。

## 选题立项卡

`10-选题立项卡.md` 至少包含：

- 最终题目与备选标题；
- 目标观众正在问的问题；
- 一句话核心判断；
- 为什么现在值得讲；
- 已确认的证据；
- 仍待核实的内容；
- 观众看完能带走的具体资产；
- 内容结构；
- 画面或演示依据；
- 与近期内容的区别；
- 最大失败风险；
- 补强动作；
- 用户的人工决定；
- 交给脚本阶段的明确要求。

不要在立项卡中偷偷扩写完整口播稿。

## 阶段状态

一次运行只处于一个状态：

`等待输入 → 信息筛选完成 → 等待进入候选 → 候选比较完成 → 等待人工决定 → 已立项 / 本轮不立项`

没有收到对应的人工决定，不得自行跃迁状态。
